# SANCTUM — 브라우저 멀티플레이 온라인 FPS

배틀그라운드·오버워치처럼 **여러 명이 같은 서버에 접속해서 함께 싸우는 3D FPS**를
웹사이트 하나로 만든 프로젝트입니다. 설치도, 플러그인도 필요 없습니다.
브라우저를 열고 주소만 공유하면 바로 같이 플레이할 수 있습니다.

```bash
npm install
npm start
# http://localhost:3000 접속
```

친구와 함께 하려면 같은 **매치 코드**를 입력하거나 `?room=코드` 링크를 공유하세요.
**봇은 없습니다.** 매치를 만들 때 **인원을 2~6명 중에서 고르고**, 그 인원이 다 모이면
경기가 시작됩니다. 다 모이지 않아도 2명 이상이면 대기 화면에서 <kbd>F</kbd>(또는
*지금 시작* 버튼)로 바로 시작할 수 있고, 그 전까지는 맵을 자유롭게 돌아다니며
기다릴 수 있습니다. 메뉴의 *진행 중인 매치* 목록에서 사람이 있는 방으로 바로 들어갈
수도 있습니다.

## 무엇이 들어있나

**게임 플레이**

- **사람끼리만 하는 진짜 멀티플레이** — 봇 없음
- **매치 인원 2~6명 선택** — 정원이 차면 시작, 덜 모여도 바로 시작 가능
- **PC와 모바일 모두 지원** — 기기를 감지해 마우스/키보드 또는 터치 조작으로 전환
- 팀 데스매치 — 두 팀(LUMEN / EMBER)이 **50킬** 또는 **8분**을 두고 경합
- 영웅 4종, 각자 다른 무기·체력·이동 속도·고유 스킬
- 헤드샷(1.5~2.2배), 거리 감쇠, 탄창/재장전, 반동과 탄퍼짐, 조준(우클릭)
- 5초 후 부활, 부활할 때 영웅 교체 가능, 스폰 무적 1.2초
- 낙하 데미지, 앉기, 달리기, 점프, 계단 오르기
- 킬로그, 스코어보드(Tab), 팀 채팅(Enter), 미니맵, 피격 방향 표시, 히트마커
- 대기 화면에서 초대 링크 복사, 메뉴에서 진행 중인 매치 목록 확인 후 바로 참가

**영웅**

| 영웅 | 역할 | 체력 | 무기 | 스킬 (Q) |
| --- | --- | --- | --- | --- |
| RANGER | Assault | 150 | AR-15 PULSE — 자동소총 | SURGE — 이동 속도 +28%, 재장전 가속 |
| SENTINEL | Tank | 260 | BREACHER-12 — 산탄총 9펠릿 | BULWARK — 5초간 피해 55% 흡수 |
| MARKSMAN | Sniper | 130 | LONGVIEW .338 — 볼트액션 | RECON — 5초간 팀 전체가 적을 벽 너머로 감지 |
| MEDIC | Support | 160 | VESPER SMG | MEND PULSE — 주변 아군 즉시 90 회복 |

**기술적으로**

- **서버 권위형(authoritative) 시뮬레이션** — 60Hz 고정 스텝, 20Hz 스냅샷
- **클라이언트 예측 + 서버 재조정(reconciliation)** — 입력이 즉시 반응하고,
  서버와 어긋나면 미확인 입력을 다시 재생해 부드럽게 보정
- **지연 보상(lag compensation)** — 서버가 최대 260ms까지 과거 위치로 되감아
  "내가 본 화면"에서의 명중을 판정
- **원격 플레이어 보간** — 100ms 과거를 렌더링해 끊김 없는 움직임
- 클라이언트와 서버가 **동일한 물리·맵·히트스캔 코드**(`shared/`)를 그대로 공유
- 외부 CDN·에셋 없음 — 텍스처, 효과음, 지형까지 전부 코드로 생성

**모델과 재질**

- **절차적 PBR** — 알베도·노멀맵(높이장 Sobel)·러프니스맵을 코드로 생성하고,
  하늘에서 만든 PMREM 환경맵으로 금속에 반사할 것을 준다
- **실제 치수의 총기** — 소총 약 90cm, 총열은 -z 방향. 1인칭과 3인칭이
  **같은 모델**을 쓰므로 상대가 든 총이 곧 내가 든 총
- **텍셀 밀도 통일** — 부품의 실제 크기에 맞춰 UV를 재조정(`parts.js`의
  `scaleUV`). 6cm 그립과 90cm 총열이 같은 밀도의 표면을 갖는다
- **관절 계층을 가진 병사** — 골반→척추→가슴→목→머리, 허벅지→정강이.
  가슴이 조준 각도를 받고 무기는 가슴에 매달린다
- **2본 IK로 잡는 손** — 양팔을 무기의 그립·전방손잡이 좌표로 매 프레임 푼다.
  무기를 바꾸거나 조준을 올려도 손이 총에서 떨어지지 않는다
- 재질별 지오메트리 병합 — 완전 무장한 병사 한 명이 드로우콜 몇 개로 끝난다

## 조작

**PC — 마우스 + 키보드**

| 키 | 동작 |
| --- | --- |
| `W` `A` `S` `D` | 이동 |
| `Shift` / `Ctrl`(`C`) / `Space` | 달리기 / 앉기 / 점프 |
| 좌클릭 / 우클릭 | 사격 / 조준 |
| `R` / `Q` | 재장전 / 영웅 스킬 |
| `Tab` / `Enter` / `Esc` | 스코어보드 / 채팅 / 마우스 해제 |
| `F` | 인원이 덜 모였을 때 경기 바로 시작 |

**모바일 · 태블릿 — 터치**

| 조작 | 동작 |
| --- | --- |
| 왼쪽 아래 스틱 | 이동 (살짝 밀면 걷기, 끝까지 밀면 달리기) |
| 화면 드래그 | 조준 |
| 화면 탭 | 단발 사격 |
| 오른쪽 버튼 | 발사 · 조준 · 점프 · 장전 · 스킬 · 앉기 |
| 왼쪽 위 버튼 | 순위 · 채팅 |
| 대기 화면 버튼 | 지금 시작 · 링크 복사 |

기기는 자동으로 감지됩니다. 손가락이 주 입력인 기기(휴대폰·태블릿)는 터치 조작으로
시작하고, 마우스가 있는 기기는 키보드/마우스로 시작합니다. **터치스크린 노트북처럼
둘 다 있는 기기는 화면을 만지면 터치 조작이 나타나고, 키보드를 쓰면 다시 사라집니다.**

터치 플레이에는 두 가지 보정이 들어갑니다. 엄지로는 마우스처럼 정밀하게 따라갈 수
없기 때문입니다.

- **조준 보정** — 조준선 근처(약 8°)에 적이 있으면 시야가 부드럽게 끌려가고, 그동안
  조준 감도가 낮아집니다.
- **자동 사격** — 적이 조준선에 들어오면 알아서 발사합니다. 메뉴에서 끌 수 있습니다.

둘 다 터치 조작에서만 동작하며, 마우스 플레이어에게는 적용되지 않습니다.
모바일에서는 시야각 80°, 그림자 끄기, 픽셀 비율 1.5배 상한이 기본값입니다.

## 매치 인원

매치를 **만드는 사람**이 메뉴에서 2~6명 중 정원을 고릅니다. 이미 있는 방에 들어갈
때는 그 방이 열릴 때 정해진 인원을 따르고, 정원이 차면 새 참가자는 거절됩니다
(다른 매치 코드를 쓰면 됩니다). 진행 중인 매치 목록에는 `3/4명`처럼 현재 인원과
정원이 함께 표시됩니다.

- 정원이 차면 워밍업 6초 후 자동 시작
- 2명 이상이면 <kbd>F</kbd> 또는 *지금 시작* 버튼으로 먼저 시작 가능
- 경기 중 상대가 모두 나가면 경기를 무효로 하고 대기 상태로 돌아갑니다

## 온라인으로 서비스하기

이 게임은 **접속 주소를 하드코딩하지 않습니다.** 클라이언트는 페이지를 내려준
호스트로 되돌아 접속하고(`ws://<그 호스트>`), HTTPS로 서비스되면 자동으로 `wss`를
씁니다. 서버는 모든 인터페이스에 바인딩하므로 코드를 고칠 필요 없이 그대로
배포하면 됩니다. 실행하면 공유할 주소가 콘솔에 출력됩니다.

**같은 네트워크(집·사무실·PC방)에서 바로**

```bash
npm start
# network http://192.168.x.x:3000  ← 이 주소를 친구에게 전달
```

### Render + GitHub 배포 (권장)

`render.yaml`이 포함되어 있어 클릭 몇 번으로 끝납니다. GitHub에 푸시할 때마다
자동 재배포됩니다.

1. 이 저장소를 GitHub에 푸시합니다(이미 되어 있으면 생략).
2. [dashboard.render.com](https://dashboard.render.com) → **New ▸ Blueprint**
3. GitHub 계정을 연결하고 이 저장소를 선택합니다.
   Render가 `render.yaml`을 읽어 설정을 자동으로 채웁니다.
4. **Apply**를 누르면 빌드(`npm ci --omit=dev`) 후 서버가 실행됩니다.
5. 2~3분 뒤 `https://sanctum-fps.onrender.com` 형태의 주소가 발급됩니다.
   그 주소를 친구에게 보내고, 같은 **매치 코드**(`?room=코드`)로 들어가면 같은
   경기에서 만납니다.

Blueprint 대신 수동으로 만들려면 **New ▸ Web Service**에서 이렇게 설정합니다.

| 항목 | 값 |
| --- | --- |
| Language / Runtime | `Node` |
| Region | `Singapore` (한국에서 지연이 가장 낮음) |
| Build Command | `npm ci --omit=dev` |
| Start Command | `node server/index.js` |
| Health Check Path | `/api/status` |
| Environment Variable | `BOTS` = `6` (선택) |

Render가 주입하는 `PORT`를 그대로 사용하고 HTTPS도 자동으로 붙습니다.
클라이언트는 그때 스스로 `wss://`로 전환하므로 **코드를 고칠 곳이 없습니다.**

알아둘 점:

- **Free 플랜은 15분간 접속이 없으면 잠들고**, 다음 접속에서 깨어나는 데
  30초~1분이 걸립니다. 경기 중에는 WebSocket이 계속 연결돼 있어 잠들지 않습니다.
  상시 대기가 필요하면 Starter 플랜으로 올리세요.
- **인스턴스는 반드시 1개로 유지하세요.** 매치 상태가 프로세스 메모리에 있어서,
  인스턴스가 여러 개면 같은 매치 코드로 들어간 두 사람이 서로 다른 프로세스에
  배정되어 서로를 보지 못합니다.

### 그 밖의 호스팅

필요한 것은 단 하나, *상시 실행되는 Node 프로세스와 WebSocket 업그레이드를
통과시키는 호스트*입니다. `Dockerfile`도 포함되어 있습니다.

```bash
fly launch --now                                    # Fly.io (Dockerfile 자동 인식)
docker build -t sanctum . && docker run -d -p 80:8080 sanctum   # VPS
```

리버스 프록시를 직접 운영한다면 WebSocket 업그레이드만 넘겨주면 됩니다
(nginx: `proxy_set_header Upgrade $http_upgrade;` +
`proxy_set_header Connection "upgrade";`).

**동작하지 않는 방식** — GitHub Pages, Netlify, Vercel의 정적 호스팅처럼
서버 프로세스를 상시 띄울 수 없는 곳에서는 멀티플레이가 불가능합니다.
권위 서버가 60Hz로 계속 돌아야 하는 구조이기 때문입니다.

규모에 대해: 한 프로세스가 여러 방을 동시에 돌리고 방 하나는 최대 12명입니다.
방이 비면 자동으로 정리되므로 작은 인스턴스 한 대로도 충분합니다.
