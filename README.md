# SANCTUM — 브라우저 멀티플레이 온라인 FPS

배틀그라운드·오버워치처럼 **여러 명이 같은 서버에 접속해서 함께 싸우는 3D FPS**를
웹사이트 하나로 만든 프로젝트입니다. 설치도, 플러그인도 필요 없습니다.
브라우저를 열고 주소만 공유하면 바로 같이 플레이할 수 있습니다.

```bash
npm install
npm start
# http://localhost:3000 접속
```

친구와 함께 하려면 같은 **매치 코드**를 입력하거나 `?room=코드` 링크를 공유하세요.
사람이 부족하면 봇이 빈자리를 채우기 때문에 혼자서도 바로 전투가 시작됩니다.

## 무엇이 들어있나

**게임 플레이**

- 팀 데스매치 — 두 팀(LUMEN / EMBER)이 **50킬** 또는 **8분**을 두고 경합
- 영웅 4종, 각자 다른 무기·체력·이동 속도·고유 스킬
- 헤드샷(1.5~2.2배), 거리 감쇠, 탄창/재장전, 반동과 탄퍼짐, 조준(우클릭)
- 5초 후 부활, 부활할 때 영웅 교체 가능, 스폰 무적 1.2초
- 낙하 데미지, 앉기, 달리기, 점프, 계단 오르기
- 킬로그, 스코어보드(Tab), 팀 채팅(Enter), 미니맵, 피격 방향 표시, 히트마커

**영웅**

| 영웅 | 역할 | 체력 | 무기 | 스킬 (Q) |
| --- | --- | --- | --- | --- |
| RANGER | Assault | 150 | AR-15 PULSE — 자동소총 | SURGE — 이동 속도 +28%, 재장전 가속 |
| SENTINEL | Tank | 260 | BREACHER-12 — 산탄총 9펠릿 | BULWARK — 5초간 피해 55% 흡수 |
| MARKSMAN | Sniper | 130 | LONGVIEW .338 — 볼트액션 | RECON — 5초간 팀 전체가 적을 벽 너머로 감지 |
| MEDIC | Support | 160 | VESPER SMG | MEND PULSE — 주변 아군 즉시 90 회복 |

**기술적으로**

- **서버 권위형(authoritative) 시뮬레이션** — 60Hz 고정 스텝, 20Hz 스냅샷
- **클라이언트 예측 + 서버 재조정(reconciliation)** — 입력이 즉시 반응하고,
  서버와 어긋나면 미확인 입력을 다시 재생해 부드럽게 보정
- **지연 보상(lag compensation)** — 서버가 최대 260ms까지 과거 위치로 되감아
  "내가 본 화면"에서의 명중을 판정
- **원격 플레이어 보간** — 100ms 과거를 렌더링해 끊김 없는 움직임
- 클라이언트와 서버가 **동일한 물리·맵·히트스캔 코드**(`shared/`)를 그대로 공유
- 외부 CDN·에셋 없음 — 텍스처, 효과음, 지형까지 전부 코드로 생성

```
  physics.js    이동/충돌/계단/레이캐스트 — 양쪽에서 똑같이 실행됨
  heroes.js     영웅·무기·스킬 수치

  index.js      정적 파일 서빙 + WebSocket 접속 처리
  room.js       권위 시뮬레이션, 히트스캔, 지연 보상, 점수/매치 진행

public/
  js/game.js       예측·재조정·보간, 사격, 카메라
  js/world.js      three.js 렌더러, 조명, 레벨 지오메트리 생성
  js/viewmodel.js  1인칭 무기(별도 씬으로 렌더링해 벽 뚫림 방지)
  js/avatars.js    상대 플레이어 모델·이름표·실루엣
  js/effects.js    탄도, 스파크, 총구 화염, 탄흔 (전부 풀링)
  js/audio.js      WebAudio로 합성한 총성·타격음·환경음
  js/hud.js, minimap.js, net.js, input.js, main.js

test/          물리, 전투, 네트워크 프로토콜 테스트 (40개)
```

## 테스트

```bash
npm test
```

물리(이동 방향이 시야와 일치하는지, 계단·벽·속도 상한), 전투(피해·헤드샷·팀킬
방지·지연 보상·스킬), 프로토콜(접속, 스냅샷, 두 클라이언트 상호 인식, 잘못된
패킷 처리)을 실제 서버를 띄워 검증합니다.

## 설정

| 환경 변수 | 기본값 | 설명 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP/WebSocket 포트 |
| `BOTS` | `6` | 방마다 채울 봇 수 (`0`이면 사람만) |

`npm install` 후 `three.js`는 `public/vendor/`로 복사되어 오프라인에서도 동작합니다.
다시 복사하려면 `npm run vendor`를 실행하세요.

## 온라인으로 서비스하기

이 게임은 **접속 주소를 하드코딩하지 않습니다.** 클라이언트는 페이지를 내려준
호스트로 되돌아 접속하고(`ws://<그 호스트>`), HTTPS로 서비스되면 자동으로 `wss`를
씁니다. 서버는 모든 인터페이스에 바인딩하므로 코드를 고칠 필요 없이 그대로
배포하면 됩니다. 실행하면 공유할 주소가 콘솔에 출력됩니다.

**같은 네트워크(집·사무실·PC방)에서 바로**

```bash
npm start
# network http://192.168.x.x:3000  ← 이 주소를 친구에게 전달
```

**인터넷에 배포** — 필요한 것은 단 하나, *상시 실행되는 Node 프로세스와 WebSocket
업그레이드를 통과시키는 호스트*입니다. `Dockerfile`이 포함되어 있습니다.

```bash
# Fly.io
fly launch --now            # Dockerfile 자동 인식
# Render / Railway / Koyeb: 저장소 연결 → Docker 선택 → 배포
# 직접 운영하는 서버(VPS)
docker build -t sanctum . && docker run -d -p 80:8080 -e BOTS=6 sanctum
```

`PORT`는 플랫폼이 주는 값을 그대로 따르고, TLS는 플랫폼의 종단에서 처리되므로
추가 설정이 없습니다. 리버스 프록시를 직접 쓴다면 WebSocket 업그레이드만
넘겨주면 됩니다(nginx: `proxy_set_header Upgrade $http_upgrade;`와
`proxy_set_header Connection "upgrade";`).

**동작하지 않는 방식** — GitHub Pages, Netlify, Vercel의 정적 호스팅처럼
서버 프로세스를 상시 띄울 수 없는 곳에서는 멀티플레이가 불가능합니다.
권위 서버가 60Hz로 계속 돌아야 하는 구조이기 때문입니다.

규모에 대해: 한 프로세스가 여러 방을 동시에 돌리고 방 하나는 최대 12명입니다.
방이 비면 자동으로 정리되므로 작은 인스턴스 한 대로도 충분합니다.
